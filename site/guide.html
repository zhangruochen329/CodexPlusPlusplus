step 01第一次启动：先做最少配置

安装后打开若尘 API 配置器。首次使用不要同时配置供应商池、模型路由和多个 Agent，先确认 Codex 能正常打开和发送一条简单消息。

1

安装并打开配置器

使用安装包完成安装，随后从开始菜单打开「若尘 API 配置器」。如果 Windows 弹出防火墙提示，允许本机应用访问专用网络。

2

选择一个接入方式

只想使用官方订阅就选「官方登录」；有中转 Base URL 和 Key 就选「纯 API」；两者都要保留再选「官方登录 + API」。

3

保存，再点击启动 Codex

等待状态显示启动完成后，再进入 Codex 发送一条短消息。第一次只验证链路，不要立即导入大量会话或打开多个实例。

推荐顺序：启动 Codex → 发送短消息 → 关闭 Codex → 再切换供应商。这样最容易判断问题来自登录、网络还是配置。

mode a直连模式：大多数用户的默认选择

直连模式就是原来的供应商切换器：配置器为 Codex 写入当前供应商的配置，Codex 直接按这份配置工作。网关开关关闭时，2.0 的其他复杂功能不会影响这条路径。

添加一个 API 供应商

  1. 进入「Codex → 供应商」。
  2. 点击「添加供应商」，填写名称、协议、Base URL、API Key 和模型列表。
  3. 点击「保存供应商」，再点卡片上的「使用」。
  4. 关闭正在运行的 Codex，回到概览点击「启动 Codex」。

模型列表怎么填

每行一个模型名。需要按模型设置上下文窗口时，可写成 模型名[窗口]，例如：

deepseek-v4-pro[1M] gpt-4.1

不确定时先填上游提供的模型名，保持最小配置。

切换规则：正在运行的 Codex 不会被强行改写。先关闭 Codex，再点击配置器的启动按钮，配置器会清理旧的本地服务并应用已保存供应商；同步失败会回滚并显示原因。

mode b网关模式：需要跨 Agent 或自动路由时再打开

网关把 Codex、Claude Code、Grok 接到同一份供应商池，可按模型路由、失败切换、多 Key 冷却和请求统计。它是可选层，不是使用 Codex 的前置条件。

适合开启网关的情况

  • 需要多个 Agent 共用供应商池。
  • 希望同一模型在多家供应商之间自动故障切换。
  • 需要查看请求、重试、Token 和费用统计。
  • 需要统一管理 MCP、Skills 或 Computer Use。

首次接入建议

  1. 进入「网关 → 供应商池」，先添加一家供应商。
  2. 在「Agent 接入」只打开 Codex。
  3. 保存后重新启动 Codex，发送短消息。
  4. 确认正常后再接入 Claude Code 或 Grok。
退出行为：接入网关的 Agent 依赖配置器运行。退出配置器后，网关接入的 Agent 会暂时连不上；需要退出后仍使用直连时，在「网关设置」开启「退出 Codex++ 时恢复直连」。

auth官方登录、官方混合 API 与旧会话

官方账号负责登录和会话身份，API 供应商负责实际请求。选择哪种模式，取决于你是否要保留官方登录。

接入方式适用场景需要填写
官方登录只使用 ChatGPT / Codex 官方订阅在 Codex 的登录页完成登录，不填写 API Key
官方登录 + API保留官方账号，同时让请求走中转或其他 API官方登录 + Base URL + API Key
纯 API不依赖官方登录，使用独立 API 凭据Base URL + API Key + 模型列表
旧会话兼容：切换到官方配置时，配置器会保留兼容旧会话所需的 custom provider 定义，并启用官方认证要求；它不是中转 Key，也不会把 API Key 写进官方登录配置。
账号安全：不要把 API Key、auth.json 或完整诊断日志发到群里。需要反馈时只提供版本、错误提示和是否能打开 Codex。

safe switch安全切换：照这个顺序最稳

A

关闭 Codex

先从 Codex 菜单退出，确认窗口和后台任务结束。不要在 Codex 正在生成回复时切换。

B

在配置器选择目标供应商

点供应商卡片的「使用」，等待切换状态结束。不要连续点击，也不要同时打开两个配置器窗口。

C

点击「启动 Codex」

普通启动会先清理残留 launcher/helper，再同步已保存配置。启动按钮恢复后再进入新会话。

D

检查当前供应商

回到配置器概览确认当前供应商名称，再发送一条短消息。成功后再继续使用长会话。

不要这样做：不要在运行中的 Codex 里切换配置后立即强杀进程，也不要把官方登录、纯 API 和网关三种模式同时改动。一次只改一个变量。

troubleshooting遇到错误时，先看这里

现象先做什么仍失败时
启动按钮无效或没有反应关闭 Codex，等待几秒后只点击一次「启动 Codex」打开「最近日志」，记录完整错误；不要反复切换供应商
stream disconnected before completion检查当前供应商、Base URL 和代理；用短消息测试切回已验证的供应商，确认直连成功后再检查网关路由
切换后旧会话不可用关闭 Codex，切回原供应商并重新启动开启历史会话修复后再试；保留失败时间和当前模式
网关接入后 Agent 连接不上确认配置器仍在运行，检查「网关 → Agent 接入」状态先断开网关接入，恢复直连，再逐个重新接入
官方订阅登录失败在 Codex/ChatGPT 内完成登录，不要填 API Key退出其他 Codex 实例后重试，避免多个实例争用同一登录态
反馈时提供：版本号（当前为 2.0.1）、接入方式、是否关闭 Codex 后切换、错误原文和最近日志中的时间。请遮住 Key、邮箱和本机路径。

  • 配置器版本显示 2.0.1。
  • 当前供应商仍是预期的那一家。
  • 官方登录状态或 API 连接状态正常。
  • 关闭 Codex 后能再次启动。
  • 网关 Agent 状态与使用前一致。

需要回退时

先关闭 Codex 和配置器，再安装之前保留的版本。不要覆盖或删除用户状态目录；如果只是供应商切换失败，优先在配置器里切回上一个已验证供应商。

faq常见问题

我只想用 API，中转模式应该怎么选？

选择「纯 API」，填写 Base URL、API Key 和模型列表；保持网关关闭，先按直连模式验证。

我需要官方订阅，还想在额度不足时走 API，选哪个？

选择「官方登录 + API」。官方账号保留登录身份，API 连接作为请求路径；两边的配置字段不要混填。

网关是不是必须开启？

不是。只使用 Codex 和单一供应商时，直连模式最简单；只有需要跨 Agent、路由或统计时才开启网关。

切换供应商后要不要重启配置器？

正常切换只需要关闭并重新启动 Codex。更换配置文件路径、导入完整配置或看到状态异常时，再完全退出并重新打开配置器。

为什么看不到某个模型？

检查模型列表是否保存、供应商是否启用该 Agent，以及当前模式是否由网关模型目录接管。先用一个明确存在的模型验证链路。
